# ⏰ 작업 스케줄러 사용 가이드

## 개요

작업 스케줄러는 CRON 표현식을 사용하여 반복 작업을 자동으로 실행하는 기능입니다. 이메일 발송, 웹훅 호출, 리포트 생성 등의 작업을 주기적으로 실행할 수 있습니다.

## 주요 기능

- ✅ **CRON 기반 스케줄링** - 다양한 반복 패턴 지원
- ✅ **작업 타입 지원** - 이메일, 웹훅, 리포트, 커스텀 작업
- ✅ **실행 히스토리** - 작업 실행 기록 및 통계
- ✅ **활성화/비활성화** - 작업을 일시정지하거나 재개할 수 있음
- ✅ **수동 실행** - 즉시 실행 가능
- ✅ **자동 재시도** - 연속 실패 시 자동 비활성화

## 작업 타입

### 1. 📧 이메일 작업

주기적으로 이메일을 자동 발송합니다.

**필수 설정:**
- 수신자 이메일
- 제목
- 내용
- HTML 형식 선택 (선택사항)

**주의사항:**
- SMTP 환경 변수 설정 필요 (`.env.local`)
  - `SMTP_HOST`
  - `SMTP_PORT`
  - `SMTP_USER`
  - `SMTP_PASS`

### 2. 🔗 웹훅 작업

외부 API를 주기적으로 호출합니다.

**필수 설정:**
- URL
- HTTP 메서드 (GET, POST, PUT, DELETE)

**선택 설정:**
- 헤더 (JSON 형식)
- 요청 본문 (JSON 형식)

**예시:**
```json
// 헤더
{
  "Authorization": "Bearer token",
  "Content-Type": "application/json"
}

// 본문
{
  "action": "sync",
  "timestamp": "2024-01-01T00:00:00Z"
}
```

### 3. 📊 리포트 작업

자동으로 리포트를 생성하고 전송합니다.

**리포트 타입:**
- `log-summary`: 로그 요약 리포트
- `document-summary`: 문서 생성 요약
- `system-status`: 시스템 상태 리포트

**전송 방법:**
- 이메일 (선택)
- Slack Webhook (선택)

### 4. ⚙️ 커스텀 작업

커스텀 스크립트를 실행합니다. (현재는 제한적 지원)

## CRON 표현식

CRON 표현식은 `분 시 일 월 요일` 형식입니다.

### 기본 예시

```
0 9 * * *     → 매일 9시
*/5 * * * *   → 5분마다
0 0 1 * *     → 매월 1일 자정
0 9 * * 1     → 매주 월요일 9시
0 12 * * *    → 매일 오후 12시
```

### 자주 사용하는 패턴

| 설명 | CRON 표현식 |
|------|------------|
| 매 분 | `* * * * *` |
| 매 5분 | `*/5 * * * *` |
| 매 10분 | `*/10 * * * *` |
| 매 시간 (0분) | `0 * * * *` |
| 매일 9시 | `0 9 * * *` |
| 매일 오후 6시 | `0 18 * * *` |
| 매주 월요일 9시 | `0 9 * * 1` |
| 매월 1일 자정 | `0 0 1 * *` |
| 평일 오전 9시 | `0 9 * * 1-5` |

### 요일 값

- `0` 또는 `7`: 일요일
- `1`: 월요일
- `2`: 화요일
- `3`: 수요일
- `4`: 목요일
- `5`: 금요일
- `6`: 토요일

## 사용 방법

### 1. 작업 생성

1. 메인 페이지에서 "작업 스케줄러" 클릭
2. "작업 생성" 탭 선택
3. 작업 정보 입력:
   - 작업 이름
   - 설명 (선택)
   - 작업 타입
   - CRON 표현식
   - 작업 타입에 맞는 설정
4. "작업 등록" 클릭

### 2. 작업 관리

**작업 목록에서 가능한 작업:**
- ✅ **활성화/비활성화**: 작업을 일시정지하거나 재개
- ▶️ **수동 실행**: 즉시 작업 실행
- 🗑️ **삭제**: 작업 삭제

### 3. 실행 히스토리 확인

각 작업의 실행 기록을 확인할 수 있습니다:
- 실행 시간
- 실행 결과 (성공/실패)
- 실행 시간 (ms)
- 오류 메시지 (실패한 경우)
- 성공률 통계

## 작업 상태

- **✅ 활성**: 정상적으로 실행 중
- **⏸️ 일시정지**: 비활성화됨
- **❌ 실패**: 연속 3회 실패 시 자동 비활성화

## 자동 보호 기능

- **연속 실패 감지**: 연속 3회 실패 시 자동 비활성화
- **실행 통계**: 성공률 모니터링
- **오류 로깅**: 실패 시 상세 오류 메시지 저장

## 환경 변수 설정

작업 타입에 따라 다음 환경 변수가 필요할 수 있습니다:

### 이메일 작업

```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASS=your-app-password
```

### 웹훅 작업

특별한 환경 변수 없음 (URL과 헤더에 직접 설정)

### 리포트 작업

- 이메일 발송 시: SMTP 설정 필요
- Slack 발송 시: Slack Webhook URL 필요

## 문제 해결

### 작업이 실행되지 않는 경우

1. **작업이 활성화되어 있는지 확인**
   - 작업 목록에서 상태 확인
   - 비활성화된 경우 "활성화" 버튼 클릭

2. **CRON 표현식 확인**
   - 올바른 형식인지 확인
   - 예시를 참고하여 수정

3. **서버 로그 확인**
   - 콘솔에서 작업 실행 로그 확인
   - 오류 메시지 확인

### 이메일 전송 실패

1. **SMTP 설정 확인**
   - `.env.local` 파일에 올바른 SMTP 설정이 있는지 확인
   - Gmail 사용 시 App Password 필요

2. **수신자 이메일 확인**
   - 올바른 이메일 주소인지 확인

### 웹훅 호출 실패

1. **URL 확인**
   - 올바른 URL인지 확인
   - 접근 가능한 URL인지 확인

2. **헤더/본문 형식 확인**
   - JSON 형식이 올바른지 확인
   - 필요한 인증 헤더가 포함되어 있는지 확인

## 예시 시나리오

### 시나리오 1: 매일 아침 리포트 발송

1. 작업 타입: **리포트**
2. 리포트 타입: **로그 요약**
3. CRON: `0 9 * * *` (매일 9시)
4. 전송 방법: 이메일 + Slack

### 시나리오 2: 매주 월요일 데이터 동기화

1. 작업 타입: **웹훅**
2. URL: `https://api.example.com/sync`
3. 메서드: POST
4. CRON: `0 9 * * 1` (매주 월요일 9시)
5. 본문: `{"action": "sync"}`

### 시나리오 3: 매 시간 상태 확인

1. 작업 타입: **리포트**
2. 리포트 타입: **시스템 상태**
3. CRON: `0 * * * *` (매 시간)
4. 전송 방법: Slack Webhook

## 제한사항

- 최근 1000개의 실행 기록만 저장
- 커스텀 작업은 현재 제한적 지원
- CRON 표현식 파싱은 기본 기능만 지원 (복잡한 패턴은 라이브러리 추가 필요)
